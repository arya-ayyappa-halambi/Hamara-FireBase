                    Enterprise Edition
                  

                  
AegisDB v2.5

                  
The High-Performance Dynamic Schema Database Engine

                

                

                  AegisDB is an enterprise-grade backend-as-a-service (BaaS) that bridges the gap between massive concurrency and uncompromising security. Engineered for modern web architectures, it combines SQLite WAL-mode performance with military-grade two-tier envelope encryption.
                

                

                  Node.js VM
                  SQLite WAL
                  AES-256 GCM
                  Firebase API
                

              

            

          


          
          

            
            

              

              

                
              

              
High-Concurrency Storage

              
Leverages SQLite in WAL (Write-Ahead Logging) mode to support highly concurrent read/write operations with zero configuration overhead.

            

            
            
            

              

              

                
              

              
Envelope Encryption

              
Enterprise-grade DEK/KEK encryption hierarchy. Data is encrypted at rest using AES-256 GCM, securing sensitive fields from unauthorized access.

            


            
            

              

              

                
              

              
VM Security Sandbox

              
Execute complex data validation rules safely. The Node.js VM sandbox allows dynamic rule evaluation without compromising system integrity.

            


            
            

              

              

                
              

              
Advanced Authentication

              
Built-in TOTP multi-factor authentication (MFA) and single-use refresh token family rotation for ironclad identity and session management.

            


            
            

              

              

                
              

              
Real-Time Telemetry

              
Deep observability powered by Prometheus endpoints. Monitor CPU, memory, and query performance in real-time through the Super Admin console.

            


            
            

              

              

                
              

              
Multi-Tenant Isolation

              
Architected for multi-tenancy. Projects operate in strict isolation, ensuring data privacy and preventing cross-contamination of resources.

            


            
            

              

              

                
              

              
Dual-Target Backups

              
Automated disaster recovery via simultaneous snapshots to Local File Systems and AWS S3 endpoints with end-to-end encryption.

            


            
            

              

              

                
              

              
Security & Incident Recovery

              
Robust mechanisms designed to securely recover from cascading failures and ensure zero data loss during schema migrations.

You are an expert full-stack engineer and cloud architect.
I want to migrate my application backend from my current stack (Firebase / Supabase / MongoDB / local state / REST) to AegisDB (a self-hosted, lightweight BaaS).

AegisDB Server Specifications:
- Base URL: http://localhost:3000 (or my configured host)
- Project API Key: Retrieve from localStorage ('aegisApiKey') or config constant. Pass in 'x-aegis-api-key' header.
- User Session: When users sign in, store their JWT token in localStorage ('aegisToken') and pass 'Authorization: Bearer <token>'.

Please systematically migrate the application according to these specifications:

1. AUTHENTICATION MIGRATION (Firebase/Supabase Auth -> AegisDB Project Auth):
   - Auth Config Discovery: GET http://localhost:3000/api/v1/project-auth/config (Header: 'x-aegis-api-key') to dynamically inspect enabled OAuth providers and registration mode.
   - User Sign-Up: POST http://localhost:3000/api/v1/project-auth/register with body { email, password, name } (Header: 'x-aegis-api-key').
   - User Sign-In: POST http://localhost:3000/api/v1/project-auth/login with body { email, password } (Header: 'x-aegis-api-key'). Returns { token, user: { id, email, name, role } }.
   - OAuth Sign-In: POST http://localhost:3000/api/v1/project-auth/oauth/<provider> (google | apple | github) with body { token: '<id_token_or_access_token>' } (Header: 'x-aegis-api-key').

2. DATABASE & DATA LAYER MIGRATION (Firestore/Postgres -> AegisDB Collections):
   - Insert Document: POST http://localhost:3000/api/v1/db/collections/<collection_name>/documents
     Headers: { 'Content-Type': 'application/json', 'x-aegis-api-key': apiKey, 'Authorization': 'Bearer <token>' }
     Body: { data: { ...fields } }
   - Query & Filter Documents: GET http://localhost:3000/api/v1/db/collections/<collection_name>/documents?filter={"status":"active"}&limit=50&offset=0&sortBy=_createdAt&sortOrder=desc
     * Translate Firestore where() clauses to server-side JSON filters in query param 'filter'.
     * Supported Operators: equality {"field":"val"} or {"field":{"$eq":"val"}}, inequality {"$ne":"val"}, comparisons {"$gt":10, "$gte":10, "$lt":100, "$lte":100}, string search {"$contains":"text"}.

/**
 * AegisClient — Official Universal Drop-in SDK for AegisDB
 * Works in Browser (Vanilla JS, React, Vue, Svelte, Next.js) and Node.js
 */
class AegisClient {
  constructor(options = {}) {
    const defaultOrigin = (typeof window !== 'undefined' && window.location && window.location.origin) ? window.location.origin : 'http://localhost:3000';
    this.baseUrl = (options.baseUrl || defaultOrigin).replace(/\/+$/, '');
    this.apiKey = options.apiKey || (typeof localStorage !== 'undefined' ? localStorage.getItem('aegisApiKey') : '') || '';
    this.token = options.token || (typeof localStorage !== 'undefined' ? localStorage.getItem('aegisToken') : '') || '';
  }

  setApiKey(key) {
    this.apiKey = key;
    if (typeof localStorage !== 'undefined') localStorage.setItem('aegisApiKey', key);
  }

  setToken(token) {
    this.token = token;
    if (typeof localStorage !== 'undefined') {
      if (token) localStorage.setItem('aegisToken', token);
      else localStorage.removeItem('aegisToken');
    }
  }

  async request(endpoint, options = {}) {
    const headers = { ...(options.headers || {}) };
    if (this.apiKey) headers['x-aegis-api-key'] = this.apiKey;
    if (this.token) headers['Authorization'] = `Bearer ${this.token}`;

    if (options.body && !(options.body instanceof FormData)) {
      headers['Content-Type'] = 'application/json';
      options.body = JSON.stringify(options.body);
    }

    const res = await fetch(`${this.baseUrl}${endpoint}`, { ...options, headers });
    const json = await res.json().catch(() => ({ success: false, message: 'Invalid server response' }));
    if (!res.ok || json.success === false) {
      throw new Error(json.message || `AegisDB request failed (${res.status})`);
    }
    return json.data !== undefined ? json.data : json;
  }

  // ── Authentication API ────────────────────────────────────────────────────────
  get auth() {
    return {
      getConfig: () => this.request('/api/v1/project-auth/config'),
      signUp: async (email, password, name) => {
        const res = await this.request('/api/v1/project-auth/register', {
          method: 'POST',
          body: { email, password, name }
        });
        if (res?.token) this.setToken(res.token);
        return res;
      },
      signIn: async (email, password) => {
        const res = await this.request('/api/v1/project-auth/login', {
          method: 'POST',
          body: { email, password }
        });
        if (res?.token) this.setToken(res.token);
        return res;
      },
      signInWithOAuth: async (provider, oauthToken) => {
        const res = await this.request(`/api/v1/project-auth/oauth/${encodeURIComponent(provider)}`, {
          method: 'POST',
          body: { token: oauthToken }
        });
        if (res?.token) this.setToken(res.token);
        return res;
      },
      signOut: () => {
        this.setToken('');
      },
      getProfile: () => this.request('/api/v1/auth/me')
    };
  }

  // ── Database & Collections CRUD API ───────────────────────────────────────────
  collection(collectionName) {
    const coll = encodeURIComponent(collectionName);
    return {
      insert: (data, id) => this.request(`/api/v1/db/collections/${coll}/documents`, {
        method: 'POST',
        body: { data, ...(id ? { id } : {}) }
      }),
      query: (options = {}) => {
        const p = new URLSearchParams();
        if (options.limit) p.set('limit', String(options.limit));
        if (options.offset) p.set('offset', String(options.offset));
        if (options.sortBy) p.set('sortBy', options.sortBy);
        if (options.sortOrder) p.set('sortOrder', options.sortOrder);
        if (options.filter) p.set('filter', typeof options.filter === 'object' ? JSON.stringify(options.filter) : options.filter);
        const q = p.toString() ? `?${p.toString()}` : '';
        return this.request(`/api/v1/db/collections/${coll}/documents${q}`);
      },
      get: (docId) => this.request(`/api/v1/db/collections/${coll}/documents/${encodeURIComponent(docId)}`),
      update: (docId, patch) => this.request(`/api/v1/db/collections/${coll}/documents/${encodeURIComponent(docId)}`, {
        method: 'PATCH',
        body: { data: patch }
      }),
      delete: (docId) => this.request(`/api/v1/db/collections/${coll}/documents/${encodeURIComponent(docId)}`, {
        method: 'DELETE'
      }),
      onSnapshot: (callback) => {
        if (typeof EventSource === 'undefined') {
          throw new Error('EventSource is not supported in this environment');
        }
        const sseUrl = `${this.baseUrl}/api/v1/db/collections/${coll}/realtime?apiKey=${encodeURIComponent(this.apiKey)}`;
        const source = new EventSource(sseUrl);
        source.onmessage = (e) => {
          try {
            const parsed = JSON.parse(e.data);
            callback(parsed);
          } catch (err) {
            console.error('Failed to parse SSE CDC payload:', err);
          }
        };
        return () => source.close();
      }
    };
  }

  // ── Storage API ───────────────────────────────────────────────────────────────
  get storage() {
    return {
      upload: async (file, filename) => {
        const formData = new FormData();
        formData.append('file', file, filename || file.name || 'upload.bin');
        return this.request('/api/v1/storage/upload', {
          method: 'POST',
          body: formData
        });
      },
      getFileUrl: (filename) => `${this.baseUrl}/api/v1/storage/assets/${encodeURIComponent(filename)}`
    };
  }
}

// Export for ES modules, CommonJS, and Browser
if (typeof window !== 'undefined') window.AegisClient = AegisClient;
if (typeof module !== 'undefined' && module.exports) module.exports = { AegisClient };
export default AegisClient;

Dual-Target Backups

      

        Never lose data with AegisDB's dual-target backup system. Backups are automatically scheduled and securely encrypted using AES-256 before being transmitted to both the Local File System and an external AWS S3-compatible cloud storage provider.
      

      
    

  


  
  

    

    

      
      

        

          

            
          

          

            
Backup & Disaster Recovery Manual

            
Comprehensive guide to configuring, monitoring, and restoring AegisDB backups.

          

        

        
      


      

        
        
        

          

            
            1. Local File System Backups
          

          

            Local backups provide the fastest recovery time objective (RTO). AegisDB automatically takes atomic snapshots of the SQLite database and stores them in a highly compressed format.
          

          

            

              

              

                Configuration
                
Enable the Local Drive Setup toggle in the Backup Configuration panel. Specify the absolute directory path where backups should be stored (e.g., /var/aegisdb/backups). Ensure the Node.js process has write permissions to this directory. A unique Generation ID will be automatically appended to each backup file to track snapshot versions and prevent overwriting.

              

            

            

              

              

                Retrieval & Restoration
                
Local backups are stored as .sqlite3.bak files. To restore, stop the AegisDB service, replace the primary aegis.db file with the desired backup file, and restart the service.

                cp /var/aegisdb/backups/aegis_20260812.sqlite3.bak ./aegis.db
npm run start
              

            

          

        


        
        

          

            
            2. AWS S3 Cloud Backups
          

          

            S3 backups provide off-site disaster recovery. Backups are streamed directly to your configured S3 bucket using multipart uploads for maximum reliability.
          

          

            

              

              

                Configuration
                
Enable the S3 Setup toggle. You must provide the Bucket Name, Region, Access Key ID, and Secret Access Key. AegisDB requires s3:PutObject and s3:ListBucket IAM permissions. Each upload receives a unique Generation ID in its object key to maintain a complete, organized snapshot history.

              

            

            

              

              

                Retrieval & Restoration
                
To restore from S3, use the AWS CLI to download the backup file to your server, then replace the primary database file.

                aws s3 cp s3://your-bucket-name/aegis_backup.sqlite3.bak ./aegis.db
npm run start
              

            

          

        


        
        

          

            
            3. Automated Scheduling & Status
          

          

            Use the Interval Dropdown to schedule automatic backups (e.g., Every 1 Hour, Daily, Weekly). AegisDB uses a built-in cron scheduler. 
            You can verify the success of the last backup by checking the Last Backup Time and the individual target statuses (Local Status / S3 Status) in the Configuration panel.
          

        


        
        

          

            
            4. Emergency Disaster Recovery Portal
          

          

            In the event of a catastrophic system failure or database corruption, AegisDB provides a dedicated, isolated Disaster Recovery portal located at /recovery.html.
          

          

            

              

              

                Drag & Drop Restoration
                
Navigate to /recovery.html and authenticate. You can drag and drop your downloaded .db.gz backup file directly into the portal. The system will securely process the backup, verify its integrity, and restore the database state. Note: You must supply the correct Master Encryption Key / Passcode to authorize the decryption and restoration process. For security reasons, this passcode is only provided to authorized personnel.
